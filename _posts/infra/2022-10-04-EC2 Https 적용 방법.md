기존에는 AWS의 ELB(로드밸런서)를 사용하여 HTTPS 설정을 해주었는데, 생각보다 비용이 나와서 깜짝 놀랐었다.

ELB는 트래픽이 없어도 **띄워두는 것만으로 시간당 요금이 붙는다.** 토이 프로젝트라 접속자가 거의 없는데도 월 고정비가 나가고 있었다.
인증서 자체는 ACM에서 무료인데, 그걸 붙이려면 ELB나 CloudFront가 필요한 구조라 결국 비용이 발생한다.

그래서 EC2 안에서 직접 인증서를 발급받아 nginx에 적용하는 방식으로 바꿨다. Let's Encrypt는 무료이고 EC2는 어차피 쓰고 있으니 추가 비용이 0이 된다.

전체 흐름은 이렇다.

1. 도메인을 준비해 EC2의 IP에 연결한다
2. Certbot으로 Let's Encrypt 인증서를 발급받는다
3. nginx에 인증서를 등록하고 80 → 443 → 애플리케이션 포트로 넘긴다

아래는 그 과정이다.

## 1. 도메인 발급

당시에는 freenom(`freenom.com`)에서 무료 도메인을 발급받아 EC2의 IP에 연결해서 썼다.

> **2023년 기준 추가**
> freenom은 무료 도메인 신규 등록을 중단했다. 지금 같은 걸 하려면 다른 방법을 써야 한다.
> - `내도메인.한국`, `kro.kr` 같은 국내 무료 도메인 서비스
> - 저렴한 유료 도메인 (`.xyz`, `.site` 등은 연 1~2달러 수준)
>
> 어느 쪽이든 **A 레코드를 EC2의 퍼블릭 IP로 지정**하는 것은 같다.

인증서를 발급받으려면 도메인이 실제로 이 서버를 가리키고 있어야 한다.
DNS 전파에 시간이 걸리므로, 다음 단계로 넘어가기 전에 `nslookup 도메인이름`으로 IP가 제대로 나오는지 확인하는 게 좋다.

EC2를 재시작하면 퍼블릭 IP가 바뀌므로 **탄력적 IP(Elastic IP)를 할당해 두는 편**이 낫다. IP가 바뀌면 도메인 연결이 끊긴다.

## 2. 인증서 요청 및 발급
Certbot을 이용해 Let's Encrypt 인증서를 발급해준다. 아래 명령어를 차례대로 실행하여 Certbot을 설치해준다.
```
sudo apt-get update
sudo apt-get install software-properties-common
sudo add-apt-repository ppa:certbot/certbot
sudo apt-get update
sudo apt-get install certbot
```

그 후 standalone 방식으로 인증 요청을 한다.

```
sudo certbot certonly --standalone -d 도메인이름
```

`standalone`은 Certbot이 **직접 임시 웹서버를 띄워** 도메인 소유를 인증하는 방식이다.
80 포트를 쓰기 때문에, 이미 nginx가 떠 있다면 먼저 내려야 한다. 안 그러면 포트 충돌로 실패한다.

```
sudo systemctl stop nginx
sudo certbot certonly --standalone -d 도메인이름
sudo systemctl start nginx
```

요청이 끝나면 `/etc/letsencrypt/live/도메인이름/` 아래에 `fullchain.pem`과 `privkey.pem` 두 개의 파일이 생긴다.

> **참고**
> `add-apt-repository ppa:certbot/certbot` 방식은 현재 권장되지 않는다. 지금은 snap으로 설치하는 쪽이 공식 안내다.
> ```
> sudo snap install --classic certbot
> ```

## 3. 인증서 등록
발급받은 인증서를 등록하기 위해 ```/etc/nginx/sites-enabled```로 이동한 후 아래 명령어를 실행한다.
```
sudo rm default
sudo nano 도메인이름.conf    # 파일 이름은 도메인 이름이 아니어도 된다. 햇갈리지 않기 위해 해주었다.
```
파일 내용을 아래 내용으로 채워준다. 스프링부트가 8081 포트에서 실행되기 때문에 80 -> 443 -> 8081 redirect를 해주었다.
```c
server {
        listen 80;
        listen [::]:80;

        location / {
                proxy_pass https://127.0.0.1;
        }
}

server {
        listen 443;

        location / {
                proxy_pass http://127.0.0.1:8081;
        }

        ssl on;
        ssl_certificate /etc/letsencrypt/live/yose.ml/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/yose.ml/privkey.pem;
}
```

설정을 바꾼 뒤에는 문법을 확인하고 반영한다.

```
sudo nginx -t          # 설정 문법 검사
sudo systemctl reload nginx
```

## 4. 인증서 갱신 (빠뜨리기 쉬운 부분)

Let's Encrypt 인증서는 **유효기간이 90일**이다. 발급만 해두고 잊으면 3개월 뒤에 사이트가 HTTPS 오류를 낸다.

Certbot을 설치하면 보통 자동 갱신 타이머가 같이 등록되는데, 확인해 두는 게 좋다.

```
sudo systemctl status certbot.timer
sudo certbot renew --dry-run     # 갱신이 정상 동작하는지 시험
```

다만 위처럼 `standalone`으로 발급받았다면 갱신할 때도 80 포트가 필요해서, nginx를 잠시 내렸다 올리는 훅을 걸어줘야 한다.

```
sudo certbot renew --pre-hook "systemctl stop nginx" --post-hook "systemctl start nginx"
```

애초에 `--nginx` 플러그인으로 발급받으면 nginx를 내리지 않고 갱신되므로 그쪽이 더 편하다.

## 지금이라면 다르게 할 부분

이 글은 2022년에 적용했던 기록이라, 지금 기준으로는 두 가지가 달라졌다.

- **`ssl on;` 지시어는 없어졌다.** 지금은 `listen 443 ssl;` 형태로 listen 줄에 붙여 쓴다.
- **80 포트는 리다이렉트로 처리하는 게 낫다.** 위 설정은 80을 `proxy_pass https://127.0.0.1`로 넘기고 있는데, `return 301 https://$host$request_uri;`로 바로 돌려보내는 쪽이 단순하고 빠르다.

정리하면 지금 쓰는 형태는 이렇다.

```
server {
    listen 80;
    server_name 도메인이름;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name 도메인이름;

    ssl_certificate     /etc/letsencrypt/live/도메인이름/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/도메인이름/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

`X-Forwarded-Proto`를 넘겨주지 않으면 스프링부트가 요청을 HTTP로 인식해서, 리다이렉트를 만들 때 `http://` 주소를 뱉는 문제가 생긴다.
ELB를 쓸 때는 신경 쓸 일이 없던 부분인데, 직접 프록시를 두면 챙겨야 한다.
