### 어떤 문제인가

**LZW 압축**을 직접 구현하는 문제다.
영문 대문자로만 이루어진 문자열이 주어지면, 압축한 결과를 사전 색인 번호 배열로 돌려주면 된다. 입력 길이는 최대 1,000자다.

사전은 A~Z가 1~26번으로 미리 채워진 상태에서 시작하고, 새로 등장한 조합은 27번부터 차례로 등록된다.

<br/>

### LZW가 하는 일

절차 자체는 짧다.

1. 현재 위치에서 **사전에 있는 가장 긴 문자열** `w`를 찾는다
2. `w`의 색인 번호를 출력한다
3. `w` 다음 글자 `c`를 붙인 `w+c`를 사전에 새로 등록한다
4. `w` 다음 위치부터 다시 1번

`KAKAO`를 예로 들면 이렇게 진행된다.

| 현재 입력(w) | 다음 글자(c) | 출력 | 사전 추가 |
|---|---|---|---|
| K | A | 11 | 27: KA |
| A | K | 1 | 28: AK |
| KA | O | 27 | 29: KAO |
| O | | 15 | |

세 번째 줄이 압축이 일어나는 지점이다. 앞에서 등록해 둔 `KA`를 두 글자가 아니라 **번호 하나(27)** 로 내보낸다.
같은 조합이 반복될수록 이득이 커지는 구조다.

<br/>

### 접근 방식

앞서 카카오 문제를 여럿 풀면서 느낀 점은 서론이 길다는 것이다.
그래서 요즘은 서론을 건너뛰고 **입출력 예제부터 보는** 버릇이 생겼는데, 이 문제도 예제를 따라가 보니 알고리즘이 금방 잡혔다.

두 글자 이상이 붙는 순간부터 27, 28, ... 이라는 번호와 함께 사전에 추가되므로 `map`을 사용했다.
`map[key] = value` 형태로 문자열을 키로 두고 번호를 값으로 담는다.

반복문 내에서는 두 가지 경우로 나뉜다.

**1. `tmp.size() == 1` 이고 사전에 없는 경우**
한 글자짜리인데 사전에 없다는 건 아직 `map`에 한 번도 넣지 않은 알파벳이라는 뜻이다.
이때는 그 글자의 번호(알파벳 순서)와, 다음 글자까지 붙인 두 글자 조합(`addNumber`)을 한꺼번에 등록한다.

**2. 그 외의 경우**
사전에서 키를 찾지 못할 때까지 길이를 늘려가다가, 못 찾으면 **바로 직전 길이의 키**에 해당하는 번호를 `answer`에 넣고 못 찾은 키를 사전에 등록한다.

```c++
m[tmp] = addNumber;
answer.push_back((m.find(msg.substr(i,j-1)))->second);
++addNumber;
--j;
```

`--j`가 없으면 다음 시작 위치가 한 칸 밀린다.
`i += j`로 다음 위치를 정하는데, `j`는 "사전에 없는" 길이까지 늘어난 값이라 실제로 소비한 길이보다 1 크기 때문이다.

<br/>

### 끝 글자 처리

```c++
msg += "0";
...
answer.pop_back();
```

이 구조는 "사전에서 못 찾는 순간"에 출력을 하므로, 마지막 문자열은 뒤에 비교할 글자가 없어 출력이 되지 않는다.
그래서 알파벳이 아닌 `"0"`을 끝에 붙여 강제로 한 번 더 불일치를 만들어 준다.

대신 그 `"0"` 때문에 `answer` 끝에 쓸모없는 값이 하나 들어가므로 `pop_back()`으로 떼어냈다.

깔끔한 방법은 아니지만, 반복문을 빠져나온 뒤 남은 문자열을 따로 처리하는 코드를 추가하는 것과 결과는 같다.

<br/>

### 시간 복잡도

바깥 반복문이 위치를 옮기고 안쪽 반복문이 길이를 늘리므로 최악의 경우 **O(n²)** 번의 `map` 조회가 일어난다.
`map`은 균형 이진 트리라 조회가 O(log k)이고, 문자열 비교 비용까지 곱해진다.

n이 1,000이라 통과하지만, 입력이 훨씬 컸다면 `unordered_map`으로 바꾸는 것만으로도 체감 차이가 컸을 것이다.

<br/>

### 풀이 코드

```c++
#include <string>
#include <vector>
#include <map>

using namespace std;

vector<int> solution(string msg) {
    vector<int> answer;
    map<string, int> m;
    int addNumber = 27;
    msg += "0";
    
    for(int i=0,j=1;i<msg.size();i+=j){     //K, A, KA, O 식으로 참조하기 위해 i+=j 사용
      for(j=1;j<msg.size()-i+1;++j){
        string tmp = msg.substr(i,j);
        if(m.find(tmp)==m.end()){
          if(tmp.size()==1){
            m[tmp] = tmp[0]-'A'+1;
            m[msg.substr(i,j+1)] = addNumber;
            answer.push_back(tmp[0]-'A'+1);
            ++addNumber;
            break;
          }
          m[tmp] = addNumber;
          answer.push_back((m.find(msg.substr(i,j-1)))->second);
          ++addNumber;
          --j;          //이걸 추가해 주지 않으면 원래 문자의 다음 문자를 참조하게 됨
          break;
        }
      }
    }
    answer.pop_back();
    
    return answer;
}
```

<br/>

### 배운 점

A~Z를 처음부터 `map`에 다 넣어두고 시작했다면 경우를 둘로 나눌 필요가 없어 코드가 훨씬 단순해졌을 것이다.
초기 상태를 제대로 세팅하는 것만으로 분기가 사라지는 경우가 있다는 걸 나중에야 알았다.
