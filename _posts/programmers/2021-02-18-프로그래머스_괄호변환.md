### 어떤 문제인가

`(`와 `)`의 개수는 같지만 짝은 맞지 않을 수 있는 문자열이 주어진다.
문제에 **변환 절차가 단계별로 그대로 제시되어 있고**, 그 절차를 따라 짝이 맞는 문자열로 바꾸면 되는 문제다.
문자열 길이는 2 이상 1,000 이하의 짝수다.

용어 두 개만 구분하면 된다.

- **균형잡힌 괄호 문자열** — `(`와 `)`의 개수가 같다
- **올바른 괄호 문자열** — 개수도 같고 짝도 맞는다

`"(()))("`는 앞의 것만 만족하고, `"(())()"`는 둘 다 만족한다.

<br/>

### 절차를 그대로 옮기면 되는 문제

이 문제는 생각보다 간단하다. 문제에 나열되어 있는 단계를 그대로 알고리즘으로 옮기면 끝이다.
알고리즘을 새로 설계하는 게 아니라 **주어진 명세를 정확히 구현하는** 유형이라, 오히려 조건을 빠뜨리지 않고 옮기는 게 관건이었다.

구현해야 할 절차는 이렇다.

1. 빈 문자열이면 그대로 반환
2. 더 이상 쪼갤 수 없는 균형잡힌 문자열 `u`와 나머지 `v`로 분리
3. `u`가 올바른 문자열이면 → `u` + (`v`를 재귀 처리한 결과)
4. `u`가 올바르지 않으면 → `"("` + (`v`를 재귀 처리) + `")"` + (`u`의 양끝을 떼고 방향을 뒤집은 것)

<br/>

### cnt 변수 하나로 두 가지를 판별한다

균형잡힌 괄호 문자열을 알아내기 위해 `cnt` 변수를 이용해 `(`와 `)`의 수가 같아지는 지점을 찾아 `u`와 `v`로 나누어 주었다.
올바른 괄호 문자열 또한 `cnt` 변수를 이용하여 판별하였다.

같은 변수를 쓰지만 세는 방식이 다르다.

**분리할 때** — `(`면 +1, `)`면 -1로 세다가 처음으로 0이 되는 지점에서 자른다.
개수가 같아지는 가장 이른 지점이므로, 그게 "더 이상 쪼갤 수 없는" 조건을 만족한다.

```c++
if (p[i] == '(') ++cnt;
else --cnt;

if (!cnt) {
    u = p.substr(0, i + 1);
    v = p.substr(i + 1);
    break;
}
```

**올바른지 판별할 때** — 같은 방식으로 세되, `cnt`가 0인 상태에서 `)`를 만나면 짝이 안 맞는다는 뜻이다.
아래 코드는 그 경우를 `++cnt`로 표시해 두고 넘어가서, 마지막에 `cnt`가 0이 아니면 올바르지 않다고 판단한다.

```c++
if (cnt == 0 && u[i] == ')') {
    ++cnt;
    continue;
}
```

### 4번 절차의 순서를 지켜야 한다

가장 실수하기 쉬운 곳이 4번이다. 붙이는 순서가 정해져 있다.

```c++
u.erase(0, 1);                    // 첫 문자 제거
u.erase(u.size() - 1, 1);         // 마지막 문자 제거
for (int i = 0; i < u.size(); ++i) {
    if (u[i] == '(') u[i] = ')';
    else u[i] = '(';
}
return "(" + checkGH(v) + ")" + u;
```

`v`를 먼저 재귀 처리해서 `(`와 `)` 사이에 넣고, **뒤집은 `u`는 그 뒤에** 붙인다.
`u`의 양끝을 떼는 것과 방향을 뒤집는 것을 헷갈려 순서를 바꾸면 답이 달라진다.

<br/>

### 시간 복잡도

재귀 한 단계마다 문자열을 훑고 `substr`로 새 문자열을 만든다.
최악의 경우(매번 앞 2글자만 떨어져 나가는 형태) 깊이가 n/2이고 각 단계가 O(n)이라 **O(n²)** 이다.
n이 1,000이라 100만 번 수준이고 제한 안에 들어온다.

<br/>

### 풀이 코드

```c++
#include <vector>
#include <string>
using namespace std;

string checkGH(string p) {
    if (p.empty()) return p;

    string u, v;

    int cnt = 0;
    for (int i = 0; i < p.size(); ++i) {
        if (p[i] == '(') ++cnt;
        else --cnt;

        if (!cnt) {
            u = p.substr(0, i + 1);
            v = p.substr(i + 1);
            break;
        }
    }

    cnt = 0;
    for (int i = 0; i < u.size(); ++i) {
        if (cnt == 0 && u[i] == ')') {
            ++cnt;
            continue;
        }
        if (u[i] == '(') ++cnt;
        else --cnt;
    }

    if (cnt == 0) {
        v = checkGH(v);
        return u + v;
    }
    else {
        u.erase(0, 1);
        u.erase(u.size() - 1, 1);
        for (int i = 0; i < u.size(); ++i) {
            if (u[i] == '(') u[i] = ')';
            else u[i] = '(';
        }
        return "(" + checkGH(v) + ")" + u;
    }
}

string solution(string p){
    return checkGH(p);
}
```

### 배운 점

명세가 길게 주어지는 문제는 알고리즘 실력보다 **읽은 걸 빠뜨리지 않고 옮기는 정확도**를 본다는 걸 알게 됐다.
이런 유형은 코드를 쓰기 전에 절차를 번호대로 적어두고, 구현하면서 하나씩 지워가는 편이 확실했다.
