### 어떤 문제인가

논문별 인용 횟수가 담긴 배열이 주어질 때, 그 연구자의 **H-Index**를 구하는 문제다.
H-Index는 "h번 이상 인용된 논문이 h편 이상"을 만족하는 h의 최댓값이다. 논문 수는 최대 1,000편, 인용 횟수는 최대 10,000회다.

<br/>

### 이해가 먼저 어려웠던 문제

이 문제는 먼저 이해하는 것이 많이 힘들었다.
정의를 읽어도 감이 안 왔는데, 예를 하나 놓고 보니 정리가 됐다.

인용 횟수가 `[3, 0, 6, 1, 5]`라면 내림차순으로 `[6, 5, 3, 1, 0]`이다.

| h | h번 이상 인용된 논문 수 | h편 이상인가 |
|---|---|---|
| 1 | 4편 (6,5,3,1) | 만족 |
| 2 | 3편 (6,5,3) | 만족 |
| 3 | 3편 (6,5,3) | 만족 |
| 4 | 2편 (6,5) | 불만족 |

만족하는 최댓값이 3이므로 H-Index는 3이다.

결국 **정렬한 뒤 앞에서부터 세다가, 인용 횟수가 지금까지 센 개수보다 작아지는 지점**이 답이라는 뜻이다.

<br/>

### 접근 방식

우선 `citations`를 `sort` 함수를 이용하여 내림차순으로 정렬해준다.
그리고 반복문 내에서 `answer`를 0번째 인덱스의 인용된 수와 비교해가며 1씩 늘린다.
해당 인덱스의 인용된 수가 `answer`보다 작거나 `answer`가 `citations`의 크기를 넘어가면 멈추고, 그때의 `answer`가 H-Index가 된다.

```c++
sort(citations.rbegin(), citations.rend());
```

`rbegin()`, `rend()`는 역방향 반복자다. `sort`에 넘기면 비교 방향이 뒤집혀 **내림차순 정렬**이 된다.
`sort(v.begin(), v.end(), greater<int>())`와 결과가 같은데, 비교 함수를 따로 안 써도 돼서 이쪽을 썼다.

반복문의 종료 조건이 두 개인 이유는 이렇다.

- `citations[answer] <= answer` — 인용 수가 지금까지 센 개수 이하로 떨어진 지점. 여기가 실제 답이다.
- `answer > citations.size()` — 모든 논문이 조건을 만족해서 배열 끝까지 간 경우. 이게 없으면 배열 범위를 넘어 참조하게 된다.

<br/>

### 시간 복잡도

정렬이 **O(n log n)**, 이후 순회가 **O(n)** 이므로 전체 **O(n log n)** 이다.
n이 최대 1,000이라 넉넉하다.

인용 횟수의 범위가 정해져 있으므로 계수 정렬(counting sort)로 O(n)에 푸는 방법도 있지만, 이 제한에서는 굳이 필요 없다.

<br/>

### 풀이 코드

```c++
#include <string>
#include <vector>
#include <algorithm>

using namespace std;

int solution(vector<int> citations) {
    int answer = 0;
    
    sort(citations.rbegin(), citations.rend());
    while(1){
        if(citations[answer]<=answer || answer>citations.size()) break;
        ++answer;
    }
    
    return answer;
}
```

<br/>

### 주의할 점

`citations.size()`는 부호 없는 정수(`size_t`)라 `int`인 `answer`와 비교하면 컴파일러가 경고를 낸다.
이 문제의 입력 범위에서는 문제가 없었지만, 습관적으로는 `(int)citations.size()`로 캐스팅하거나 `answer`를 `size_t`로 두는 편이 안전하다.

또 종료 조건 두 개의 **순서**가 중요하다. `citations[answer]`를 먼저 평가하므로, 범위를 넘어선 접근이 먼저 일어날 수 있는 구조라면 조건 순서를 바꿔야 한다.
