Go 문법을 훑고 나서, 배운 걸 실제로 굴려보려고 작은 예제 두 개를 만들었다.
계좌(BankAccount)와 사전(Dictionary)인데, 둘 다 코드는 짧지만 Go에서 **타입에 동작을 붙이는 방식**과 **에러를 값으로 다루는 방식**이 그대로 드러난다.

다른 언어의 클래스에 익숙하다면 이 두 예제가 가장 헷갈리는 지점이기도 해서, 코드와 함께 왜 이렇게 쓰는지를 같이 정리했다.

<br/>

## 1. BankAccount - 포인터 리시버와 커스텀 에러

계좌에 입금하고, 출금하고, 잔액을 조회하는 예제다.

```go
package accounts

import (
	"errors"
	"fmt"
)

// Account struct
type Account struct {
	owner   string
	balance int
}

var errnoMoney = errors.New("Can't withdraw")

// NewAccount creates Account
func NewAccount(owner string) *Account {
	account := Account{owner: owner, balance: 0}
	return &account
}

// Deposit x amount on your account
func (a *Account) Deposit(amount int) {
	a.balance += amount
}

// Balance of your account
func (a Account) Balance() int {
	return a.balance
}

// Withdraw x amount from your account
func (a *Account) Withdraw(amount int) error {
	if a.balance < amount {
		return errnoMoney
	}
	a.balance -= amount
	return nil		//nil = null, err no exist
}

// ChangeOnwer of the account
func (a *Account) ChangeOwner(newOwner string) {
	a.owner = newOwner
}

func (a Account) Owner() string {
	return a.owner
}

func (a Account) String() string {
	return fmt.Sprint(a.Owner(), "'s account.\nHas: ", a.Balance())
}

```

```go
package main

import (
	"fmt"

	"github.com/y00913/learngo/accounts"
)

func main() {
	account := accounts.NewAccount("nico")
	account.Deposit(10)
	fmt.Println(account)
}

```

### 값 리시버와 포인터 리시버

여기서 제일 중요한 건 함수 앞에 붙은 `(a Account)`와 `(a *Account)`의 차이다.

```go
func (a *Account) Deposit(amount int)   // 포인터 리시버
func (a Account) Balance() int          // 값 리시버
```

Go는 기본이 **값 복사**다. `(a Account)`로 받으면 메서드 안의 `a`는 원본이 아니라 복사본이다.
그래서 값 리시버로 `a.balance += amount`를 해봤자 복사본만 바뀌고 원본 계좌는 그대로다. 컴파일 에러도 안 나서 더 헷갈린다.

반대로 `(a *Account)`는 주소를 받으므로 원본을 고칠 수 있다. 그래서 규칙은 단순하다.

- **상태를 바꾸는 메서드**(`Deposit`, `Withdraw`, `ChangeOwner`) → 포인터 리시버
- **읽기만 하는 메서드**(`Balance`, `Owner`) → 값 리시버도 됨

`NewAccount`가 `*Account`를 리턴하는 것도 같은 이유다. 값으로 리턴하면 이후에 포인터 메서드를 부를 때 매번 주소를 따로 잡아야 한다.

### 에러를 미리 만들어 두는 이유

```go
var errnoMoney = errors.New("Can't withdraw")
```

에러를 함수 안에서 매번 `errors.New(...)`로 만들지 않고 패키지 수준 변수로 빼 뒀다.
이렇게 해야 호출하는 쪽에서 `if err == errnoMoney` 처럼 **어떤 에러인지 구분**할 수 있기 때문이다.
매번 새로 만들면 메시지는 같아도 서로 다른 값이라 비교가 안 된다.

Go에는 예외(exception)가 없고 에러가 그냥 리턴값이다. 그래서 `Withdraw`는 성공하면 `nil`, 실패하면 에러 값을 돌려준다.

### String() 을 정의하면 출력이 바뀐다

```go
func (a Account) String() string {
	return fmt.Sprint(a.Owner(), "'s account.\nHas: ", a.Balance())
}
```

`main`에서 `fmt.Println(account)`를 했는데 구조체 내용이 아니라 사람이 읽을 문장이 찍힌다.
`String() string` 메서드가 있으면 `fmt`가 출력할 때 그걸 대신 쓰기 때문이다.
Java의 `toString()`과 같은 역할인데, Go에서는 상속이나 선언 없이 **메서드 이름만 맞으면** 자동으로 적용된다.

## 2. Dictionary - map에 메서드를 붙이기

단어를 넣고, 찾고, 수정하고, 지우는 사전이다.

```go
package mydict

import "errors"

// Dictionary type
type Dictionary map[string]string

var (
	errNotFound   = errors.New("Not Found")
	errCantUpdate = errors.New("Cant update non-existing word")
	errWordExists = errors.New("That word  already exists")
)

// Search for a word
func (d Dictionary) Search(word string) (string, error) {
	value, exists := d[word]
	if exists {
		return value, nil
	}
	return "", errNotFound
}

// Add a word to the dictionary
func (d Dictionary) Add(word, def string) error {
	_, err := d.Search(word)
	switch err {
	case errNotFound:
		d[word] = def
	case nil:
		return errWordExists
	}

	return nil
}

// Update a word
func (d Dictionary) Update(word, definition string) error {
	_, err := d.Search(word)
	switch err {
	case nil:
		d[word] = definition
	case errNotFound:
		return errCantUpdate
	}
	return nil
}

// Delete a word
func (d Dictionary) Delete(word string) {
	delete(d, word)
}

```
```go
package main

import (
	"fmt"

	"github.com/y00913/learngo/mydict"
)

func main() {
	dictionary := mydict.Dictionary{"first": "First word"}
	baseWord := "hello"
	dictionary.Add(baseWord, "First")
	dictionary.Search(baseWord)
	dictionary.Delete(baseWord)
	word, err := dictionary.Search(baseWord)
	if err != nil {
		fmt.Println(err)
	} else {
		fmt.Println(word)
	}
}

```

### map에 직접 메서드를 붙일 수 있다

```go
type Dictionary map[string]string
```

이 한 줄이 이 예제의 핵심이다. `map[string]string`에 `Dictionary`라는 이름을 붙여 **새 타입**을 만들었다.
Go에서는 이렇게 내가 정의한 타입에는 메서드를 붙일 수 있어서, 구조체로 감싸지 않고도 `Search`, `Add` 같은 동작을 map에 직접 달 수 있다.

여기서는 리시버가 `(d Dictionary)` — 값 리시버인데도 `d[word] = def`가 원본에 반영된다.
`Account` 때와 반대로 보이지만 이유가 있다. **map은 내부적으로 참조 타입**이라, 복사해도 같은 데이터를 가리키기 때문이다.
슬라이스와 채널도 마찬가지다. 구조체와 헷갈리기 쉬운 부분이다.

### comma ok 패턴

```go
value, exists := d[word]
```

map에서 값을 꺼낼 때 두 번째 리턴값으로 **키가 실제로 있었는지**를 받을 수 있다.
이걸 안 쓰면 없는 키를 꺼내도 에러가 아니라 타입의 기본값(문자열이면 `""`)이 나와서, 값이 빈 문자열인 건지 키가 없는 건지 구분할 수 없다.

`Add`와 `Update`가 `Search`를 먼저 부르는 것도 이 때문이다. 존재 여부를 확인해서 각각 다른 에러를 돌려준다.

- `Add` — 이미 있으면 `errWordExists`
- `Update` — 없으면 `errCantUpdate`

에러를 `switch err`로 분기하는 방식은, 앞서 계좌 예제에서 에러를 변수로 빼 뒀기에 가능한 것이다.

## 정리하며

두 예제를 만들면서 정리된 건 결국 세 가지다.

- 상태를 바꿀 거면 포인터 리시버, 읽기만 하면 값 리시버. 단 map·슬라이스는 값 리시버여도 원본이 바뀐다.
- 에러는 예외가 아니라 리턴값이고, 구분해야 하면 패키지 변수로 미리 만들어 둔다.
- `String()`처럼 이름만 맞추면 동작이 끼워지는 방식이 Go의 인터페이스 개념으로 이어진다.

코드 자체는 30줄짜리인데, 다른 언어를 쓰다 넘어오면 걸리는 지점이 이 안에 거의 다 들어 있었다.
