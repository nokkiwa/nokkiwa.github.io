여러 URL이 살아 있는지 확인하는 프로그램을 만들어보면서, Go가 왜 동시성으로 이름이 났는지를 체감할 수 있었다.
같은 일을 싱글 스레드로 한 번, goroutine으로 한 번 짜서 비교해봤다.

<br/>

## 싱글 스레드 방식

아래 코드는 싱글 스레드를 이용한 방식으로 시간이 많이 걸린다. 파이썬과 같은 방식이라고 보면 된다.

URL 9개를 `for`문으로 하나씩 돌면서 `http.Get`을 호출한다.
문제는 `http.Get`이 **응답이 올 때까지 그 자리에서 멈춰 있는다**는 점이다.
한 요청에 1초가 걸린다면 9개를 확인하는 데 9초가 걸린다. 대기 시간이 그대로 쌓인다.

네트워크 요청은 CPU가 일하는 게 아니라 **응답을 기다리는** 시간이 대부분이라, 이 대기를 겹치게만 해도 전체 시간이 크게 줄어든다.

<br/>

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
)

var errRequestFailed = errors.New("Requset failed")

func main() {
	var results = make(map[string]string)       //make는 빈 map을 만들어줌, 혹은 var results = map[string]string{} 으로도 가능
	urls := []string{
		"https://www.airbnb.com/",
		"https://www.google.com/",
		"https://www.amazon.com/",
		"https://www.reddit.com/",
		"https://www.google.com/",
		"https://soundcloud.com/",
		"https://www.facebook.com/",
		"https://www.instagram.com/",
		"https://academy.nomadcoders.co/",
	}
	for _, url := range urls {
		result := "OK"
		err := hitURL(url)
		if err != nil {     //에러 발견
			result = "FAILED"
		}
		results[url] = result
	}
	for url, result := range results {
		fmt.Println(url, result)
	}
}

func hitURL(url string) error {
	fmt.Println("Checking:", url)
	resp, err := http.Get(url)
	if err != nil || resp.StatusCode >= 400 {
		fmt.Println(err, resp.StatusCode)
		return errRequestFailed
	}
	return nil
}

```

## Goroutines

goroutine은 함수 호출 앞에 **`go` 한 단어만 붙이면** 그 함수가 별도의 흐름에서 실행되는 방식이다.
싱글 스레드로 순차 실행되던 것을 여러 흐름으로 나눠준다고 보면 된다.

![](/public/img/goroutine.png)

OS 스레드를 직접 만드는 게 아니라 Go 런타임이 관리하는 가벼운 실행 단위라, 수천 개를 만들어도 부담이 적은 것이 특징이다.

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	go sexyCount("nico") //goroutines는 main 함수가 작동하는 동안만 유효
	go sexyCount("flynn")
	time.Sleep(time.Second * 5)
}

func sexyCount(person string) {
	for i := 0; i < 10; i++ {
		fmt.Println(person, "is sexy", i)
		time.Sleep(time.Second)
	}
}

```
### main이 끝나면 전부 사라진다

위 코드에서 `time.Sleep(time.Second * 5)`가 없으면 아무것도 출력되지 않는다.

goroutine은 **main 함수가 살아 있는 동안만 유효하기** 때문이다.
`go sexyCount(...)`는 "이 함수를 시작해 두고 다음 줄로 넘어가라"는 뜻이라, main이 바로 끝나버리면 시작된 goroutine도 같이 사라진다.

여기서는 5초를 재워서 시간을 벌었는데, 이건 어디까지나 확인용이다.
실제로는 얼마나 걸릴지 모르는 작업을 `Sleep`으로 기다릴 수 없으니, **채널(channel)** 로 "끝났다"는 신호를 받아야 한다.

```go
func main() {
	c := make(chan string)
	urls := []string{ /* ... */ }

	for _, url := range urls {
		go hitURL(url, c)      // 전부 동시에 시작
	}
	for i := 0; i < len(urls); i++ {
		fmt.Println(<-c)       // 완료된 것부터 하나씩 받는다
	}
}
```

`<-c`는 채널에 값이 들어올 때까지 기다린다.
URL 개수만큼 받으면 모든 goroutine이 끝났다는 뜻이므로, `Sleep`처럼 시간을 찍어두지 않아도 된다.

이렇게 하면 9개 요청이 동시에 나가므로 전체 시간이 **가장 느린 요청 하나** 수준으로 줄어든다.

<br/>

### 정리하며

- `go` 키워드 하나로 함수를 별도 흐름에서 돌릴 수 있다
- goroutine은 main보다 오래 살지 못한다
- 결과를 모으거나 완료를 기다릴 때는 `Sleep`이 아니라 채널을 쓴다

병렬 처리를 이렇게 쉽게 표현할 수 있다는 점이 Go의 장점인 것 같다.
다만 쉬운 만큼 "언제 끝나는지"를 관리하지 않으면 결과가 통째로 사라져서, 채널을 같이 익혀야 실제로 쓸 수 있는 도구가 된다.
