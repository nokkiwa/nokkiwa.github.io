운영 중인 다른 Jekyll 블로그의 `_config.yml`을 보다가 `timezone` 설정이 빠져 있는 걸 발견했다. 글은 전부 `+0900`으로 쓰고 있으니 `timezone: Asia/Seoul`을 넣으면 깔끔해지겠다고 생각했다.

넣기 전에 빌드 결과를 비교해봤는데, 이미 발행된 글 17개의 주소가 바뀌는 걸 확인했다. 그대로 배포했으면 17개 글이 전부 404가 날 뻔했다.

### 1. 증상

해당 블로그의 퍼머링크 형식은 날짜가 들어가는 기본값이다.

```yaml
permalink: /:categories/:year/:month/:day/:title:output_ext
```

글 머리말에는 이렇게 한국 시간으로 적혀 있다.

```yaml
date: 2026-03-10 07:30:00 +0900
```

그런데 실제 발행된 주소는 `/2026/03/09/...`였다. 날짜가 하루 앞으로 밀려 있었다.

### 2. 재현

작은 테스트 사이트를 만들어서 확인했다. 오전 7시 30분 글과 오후 9시 글을 하나씩 만들고, 빌드 환경을 GitHub Actions와 같은 UTC로 맞췄다.

```bash
# timezone 설정 없이
TZ=UTC jekyll build -d out1
# out1/2026/03/09/early.html   <- 오전 7시 30분 글
# out1/2026/03/10/late.html    <- 오후 9시 글

# _config.yml 에 timezone: Asia/Seoul 추가 후
TZ=UTC jekyll build -d out2
# out2/2026/03/10/early.html
# out2/2026/03/10/late.html
```

`timezone`이 없으면 Jekyll은 **빌드하는 머신의 시간대**로 날짜를 계산한다. GitHub Actions 러너는 UTC다. 한국 시간 오전 7시 30분은 UTC로 전날 오후 10시 30분이니, 주소에 들어가는 날짜가 전날이 된다.

한국 시간 0시~9시 사이에 쓴 글만 이렇게 된다. 오후에 쓴 글은 UTC로 바꿔도 같은 날이라 티가 안 난다. 그래서 오래 모르고 지나갔다.

### 3. 고치면 생기는 문제

설정만 보면 `timezone: Asia/Seoul`을 넣는 게 맞다. 하지만 이미 발행된 글 입장에서는 주소가 바뀌는 것이다.

- 검색엔진에 색인된 주소 `/2026/03/09/early.html`이 404가 된다.
- 외부에서 걸어둔 링크도 전부 깨진다.
- 새 주소는 검색엔진이 처음 보는 페이지라 다시 색인돼야 한다.

해당 블로그는 검색 유입이 주 트래픽이라 17개 글 주소가 한꺼번에 깨지는 건 손해가 컸다.

### 4. 선택지

1. **그대로 둔다.** 날짜가 하루 밀리는 것 말고는 동작에 문제가 없다.
2. **설정을 고치고 리다이렉트를 건다.** `jekyll-redirect-from` 플러그인으로 옛 주소를 새 주소로 넘길 수 있다. 17개 글마다 `redirect_from`을 달아야 한다.
3. **글마다 `permalink`를 고정한다.** 머리말에 주소를 직접 박아두면 설정과 무관하게 유지된다.

나는 1번을 골랐다. 주소에 찍힌 날짜가 하루 틀린 건 독자가 거의 신경 쓰지 않는다. 반면 주소가 깨지면 유입이 바로 줄어든다. 대신 설정 파일에 이유를 주석으로 남겨 나중에 누가 "고치지" 않게 했다.

새로 만드는 블로그라면 반대다. **첫 글을 올리기 전에** `timezone`부터 넣어두면 이런 고민을 할 일이 없다. 지금 이 블로그(KLOG)는 처음부터 넣어두었다.

```yaml
timezone: Asia/Seoul
```

### 덤: 빌드 폴더가 다음 빌드에 섞여 들어간다

테스트하면서 하나 더 걸렸다. 두 번째 빌드 결과에 `out2/out1/...`이 생겼다. `-d out1`로 만든 폴더가 사이트 소스 폴더 안에 있어서, 다음 빌드 때 일반 파일처럼 복사된 것이다. Jekyll은 기본 출력 폴더인 `_site`만 알아서 제외한다. 다른 이름으로 빌드할 거면 소스 밖 경로(`/tmp/...`)를 쓰거나 `_config.yml`의 `exclude`에 넣어야 한다.
