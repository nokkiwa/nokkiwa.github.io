우분투 22.04에 도커를 설치하고 실행했더니 서비스가 아예 뜨지 않았다.
재설치를 몇 시간 반복해도 같은 오류가 나와서, 결국 **찌꺼기까지 전부 지우고 다시 설치**해서야 해결됐다. 그 과정을 남겨둔다.

### 증상
```bash
Job for docker.service failed because the control process exited with error code.
See "systemctl status docker.service" and "journalctl -xe" for details.
```

```systemctl status docker```를 통해 도커 상태를 보니 아래와 같은 오류가 있었다
```bash
docker.service: Start request repeated too quickly.
docker.service: Failed with result 'exit-code'.
Failed to start Docker Application Container Engine.
```
<br>

### 오류 메시지 읽기

`Start request repeated too quickly`는 그 자체가 원인이 아니다.
systemd는 서비스가 죽으면 자동으로 재시작하는데, **짧은 시간에 너무 여러 번 실패하면 재시도를 포기하고** 이 메시지를 낸다.

즉 "도커가 계속 죽고 있다"는 결과만 알려줄 뿐, 왜 죽는지는 안 나온다. 진짜 원인은 다른 곳에서 찾아야 한다.

```bash
sudo journalctl -u docker.service -n 50 --no-pager
```

데몬이 남긴 실제 로그는 여기에 있다. 나는 설치 과정에서 데몬 설정이 꼬인 것으로 판단했다.

### 완전히 지우고 다시 설치하기

도커를 제거하고 다시 설치하려고 했는데, 몇 시간 동안 재설치를 반복해도 같은 오류가 계속 나왔다.

`apt remove`만으로는 **설정 파일과 데이터 디렉터리가 남기 때문**이었다.
재설치를 해도 망가진 설정을 그대로 다시 읽어서 똑같이 죽는 것이다. 있는 대로 다 삭제하고 다시 설치하니 잘 실행되었다.

아래는 그 과정이다. 참고로 나는 우분투 22.04를 사용 중이다.

> **주의**
> `/var/lib/docker`를 지우면 **이미지·컨테이너·볼륨이 전부 사라진다.**
> 살려야 할 데이터가 있다면 먼저 백업하고 진행해야 한다. 이제 막 설치한 서버가 아니라면 특히 조심할 것.

<br>
먼저 도커 관련 데몬들을 멈춘다.

```bash
sudo systemctl stop docker.socket
sudo systemctl disable docker.socket
sudo systemctl stop docker.service
```
다음으로 도커 관련된 모든 패키지들을 제거해준다.

```bash
dpkg -l | grep -i docker 
```
도커 관련 패키지들을 위 명령어로 찾아준다.
```bash
sudo apt-get purge -y <package_name>
```
찾은 패키지들을 모두 위 명령어로 제거해준다.

<br>
그리고 아래 명령어들을 차례대로 실행한다.

```bash
sudo rm -rf /var/lib/docker* /etc/docker*
sudo rm -rf /var/run/docker.sock /var/run/dockershim.sock /var/run/docker.pid
sudo rm -rf /var/lib/dockershim /var/run/docker /var/run/dockershim.sock
sudo apt purge docker-ce docker-ce-cli containerd.io
```

<br>
아래 명령어들을 차례대로 실행해 도커를 설치해준다. (우분투 22.04 기준)

```bash
sudo apt-get update
sudo apt-get install apt-transport-https ca-certificates curl gnupg-agent software-properties-common
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo apt-key add -
sudo add-apt-repository "deb [arch=amd64] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable"
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io
```

<br>

설치가 끝나면 상태를 확인한다.

```bash
sudo systemctl status docker
sudo docker run hello-world
```

`hello-world`가 정상 출력되면 데몬과 런타임이 모두 살아 있다는 뜻이다.

### 정리

- `Start request repeated too quickly`는 **원인이 아니라 결과**다. `journalctl`로 진짜 로그를 봐야 한다.
- 재설치가 안 먹히면 `apt remove`가 아니라 **설정·데이터까지 남아 있는지**를 의심한다.
- 지우기 전에 `/var/lib/docker`에 살릴 데이터가 있는지 먼저 확인한다.

같은 명령을 반복하는데 결과가 똑같다면, 명령이 잘못된 게 아니라 **지워졌다고 생각한 무언가가 남아 있는** 경우가 많다는 걸 배웠다.

> **참고**
> 위 설치 명령에 있는 `apt-key add`는 현재 권장되지 않는 방식이다.
> 지금은 `/etc/apt/keyrings/`에 GPG 키를 두고 저장소 항목에서 `signed-by`로 지정하는 방식이 도커 공식 문서의 안내다.
