웹소켓 기반 채팅을 붙이면서, 메시지 브로커로 RabbitMQ를 외부 서버 도커에 올리고 스프링부트와 연결을 시도했는데 연결이 계속 실패했다.

애플리케이션 로그에는 브로커에 연결하지 못했다는 메시지만 반복해서 찍혔다.
설정값(호스트, 포트, 계정)을 몇 번씩 확인해도 틀린 곳이 없어서 한참 헤맸는데, 결론부터 말하면 **스프링 쪽이 아니라 RabbitMQ 쪽 설정 문제**였다.

### 어떤 구조인가

`enableStompBrokerRelay`는 스프링이 직접 메시지를 중계하지 않고, **외부 브로커에 STOMP 프로토콜로 넘기는** 방식이다.
그래서 RabbitMQ가 STOMP를 알아들을 수 있어야 하는데, RabbitMQ는 기본적으로 AMQP만 켜져 있고 STOMP는 **플러그인으로 따로 활성화**해야 한다.

포트 `61613`도 STOMP 플러그인이 켜져 있을 때 열리는 포트다. 플러그인이 꺼져 있으면 그 포트로 연결 자체가 안 된다.

`config` 설정은 아래와 같이 해주었었다.
```java
@Slf4j
@Configuration
@EnableWebSocketMessageBroker
public class StompConfig implements WebSocketMessageBrokerConfigurer {
    @Value("${host}")
    private String Host;
    @Value("${relayPort}")
    private int relayPort;
    @Value("${clientId}")
    private String clientId;
    @Value("${clientPw}")
    private String clientPw;

    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry){
        registry.setApplicationDestinationPrefixes("/pub")
                .enableStompBrokerRelay("/topic")
                .setRelayHost(Host)
                .setVirtualHost("/")
                .setRelayPort(relayPort)		// 61613
                .setClientLogin(clientId)		// guest
                .setClientPasscode(clientPw);	// guest
    }

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry){
        registry.addEndpoint("/ws").setAllowedOriginPatterns("*").withSockJS();
    }
}
```

### 원인과 해결

이유는 도커에 올린 RabbitMQ에서 **web stomp 플러그인 설정을 해주지 않아서**였다.

컨테이너에 들어가 플러그인을 켜고 재시작해주면 연결된다. 아래 명령어를 차례로 입력하면 된다.

```
# docker exec -it <rabbitMQ 컨테이너> /bin/bash
```
```
# rabbitmq-plugins enable rabbitmq_web_stomp
```
```
# rabbitmqctl stop
# rabbitmqctl start_app
# rabbitmqctl status
```
`rabbitmqctl status`의 출력에서 `rabbitmq_web_stomp`가 실행 중인 플러그인 목록에 들어 있으면 정상이다.

### 확인해볼 순서

같은 증상을 다시 만난다면 이 순서로 좁히는 게 빨랐을 것 같다.

1. **포트가 열려 있나** — 브로커 서버에서 `61613` 포트가 LISTEN 상태인지 확인한다. 안 열려 있으면 플러그인 문제다.
2. **플러그인이 켜져 있나** — `rabbitmq-plugins list`로 확인한다.
3. **도커 포트 매핑이 되어 있나** — 컨테이너를 띄울 때 `-p 61613:61613`을 빠뜨리면 플러그인을 켜도 밖에서 접근할 수 없다.
4. **계정 권한이 맞나** — 기본 `guest` 계정은 보안상 **localhost에서만** 접속이 허용된다. 외부 서버에 올렸다면 별도 계정을 만들어야 한다.

설정값을 아무리 봐도 안 될 때는 **연결을 받는 쪽이 그 프로토콜을 지원하는지**부터 확인하는 게 순서라는 걸 배웠다.
