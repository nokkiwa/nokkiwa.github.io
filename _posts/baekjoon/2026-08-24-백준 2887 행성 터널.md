[2887번: 행성 터널](https://www.acmicpc.net/problem/2887)

### 어떤 문제인가

3차원 공간에 행성 `N`개가 있고, 두 행성을 잇는 터널의 비용은 **`min(|xA-xB|, |yA-yB|, |zA-zB|)`** 이다.
모든 행성이 서로 오갈 수 있도록 터널을 뚫을 때의 최소 비용을 구하는 문제다.

`N`은 최대 100,000이고 좌표는 -10억 ~ 10억이다.

<br>

### 알고리즘은 바로 보이는데, 그게 문제가 아니다

"모든 정점을 최소 비용으로 연결"이니 최소 스패닝 트리라는 건 금방 떠오른다.
문제는 **간선이 몇 개냐**는 것이다.

행성이 100,000개면 모든 쌍의 개수는 대략 50억 개다. 이걸 다 만들면 메모리부터 터진다.
그래서 이 문제의 핵심은 크루스칼이 아니라 **어떤 간선만 만들어도 충분한가**를 찾는 것이다.

<br>

### 왜 인접한 좌표만 보면 되는가

비용 식을 다시 보자.

```
min(|xA-xB|, |yA-yB|, |zA-zB|)
```

세 축 중 **하나의 값만 실제로 쓰인다.** 그러면 이렇게 뒤집어 생각할 수 있다.

- x축만 놓고 봤을 때 최소 비용이 되는 간선들
- y축만 놓고 봤을 때
- z축만 놓고 봤을 때

이 셋을 다 모으면, MST에 필요한 간선은 반드시 그 안에 들어 있다.

그리고 한 축에서 의미 있는 간선은 **정렬했을 때 바로 옆에 있는 것들뿐이다.**
정렬된 상태에서 1번과 3번을 잇는 비용은 (1↔2) + (2↔3)보다 절대 싸지 않기 때문에, 떨어진 쌍을 볼 이유가 없다.

결국 축마다 `N-1`개씩, 총 `3(N-1)`개의 간선만 만들면 된다. 50억 개가 30만 개로 줄어든다.

<br>

### 접근 방식

우선 주어지는 좌표에서 `x`, `y`, `z`를 각각의 벡터에 **원래 인덱스와 함께** 저장한다.

```cpp
x.push_back({ a,i });
y.push_back({ b,i });
z.push_back({ c,i });
```

정렬하면 순서가 뒤섞이므로, 이 간선이 원래 몇 번 행성이었는지를 잃지 않으려면 인덱스를 같이 들고 다녀야 한다.
`pair`의 첫 원소를 좌표로 둔 건 `sort`가 첫 원소 기준으로 정렬해주기 때문이다.

그 다음 세 축을 각각 정렬하고, 인접한 것끼리 차이를 구해 간선으로 만든다.

```cpp
for (int i = 0; i < N - 1; i++) {
    v.push_back({ abs(x[i].first - x[i + 1].first),{x[i].second, x[i + 1].second} });
    v.push_back({ abs(y[i].first - y[i + 1].first),{y[i].second, y[i + 1].second} });
    v.push_back({ abs(z[i].first - z[i + 1].first),{z[i].second, z[i + 1].second} });
}
```

이후는 [1647 도시 분할 계획](/baekjoon/2026/08/27/백준-1647-도시-분할-계획.html)과 똑같은 크루스칼이다.
간선을 정렬하고, 유니온 파인드로 사이클을 피하면서 싼 것부터 채택한다.

<br>

### 시간 복잡도

- 축별 정렬 3번: **O(N log N)**
- 간선 `3(N-1)`개 정렬: **O(N log N)**
- 크루스칼: 간선 수에 거의 비례

전체 **O(N log N)** 이다. 모든 쌍을 만드는 O(N²)와는 비교가 안 된다.

<br>

### 배운 점

생각보다 까다로웠던 문제였다.
크루스칼 알고리즘을 사용한다는 점은 바로 떠올릴 수 있었는데, **이를 사용하기 위해 주어진 값을 어떻게 가공해야 할지** 아이디어가 잘 떠오르지 않았다.

결국 문제에 주어진 거리 공식을 보고 아이디어를 떠올릴 수 있었다.
`min`이 붙어 있다는 건 "세 축을 따로 봐도 된다"는 힌트였는데, 처음에는 그냥 거리 계산식으로만 읽고 넘어갔다.

**알고리즘을 정하고 나서도 입력을 그 알고리즘이 먹을 수 있는 형태로 바꾸는 단계가 따로 있다**는 걸 배웠다.
[1774 우주신과의 교감](/baekjoon/2026/08/02/백준-1774-우주신과의-교감.html)도 같은 성격이었는데, 그쪽은 N이 작아서 모든 쌍을 만들어도 됐던 차이가 있다.

한 가지 더. 가중치 합을 `int result`로 두었는데, 간선이 10만 개 가까이 되는 문제에서는 합이 `int` 범위를 넘길 여지가 있으니 `long long`으로 두는 편이 안전하다.

<br>

---

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cmath>

using namespace std;

int N, result = 0;
vector<pair<int, pair<int, int>>> v;
vector<pair<int, int>> x;
vector<pair<int, int>> y;
vector<pair<int, int>> z;
int p[100000];

int findParent(int a) {
    if (a == p[a]) return a;
    else return p[a] = findParent(p[a]);
}

void unionParent(int a, int b) {
    a = findParent(a);
    b = findParent(b);

    if (a != b) p[a] = b;
}

bool sameParent(int a, int b) {
    a = findParent(a);
    b = findParent(b);

    if (a == b) return true;
    else return false;
}

void findRoute() {
    sort(x.begin(), x.end());
    sort(y.begin(), y.end());
    sort(z.begin(), z.end());

    for (int i = 0; i < N - 1; i++) {
        v.push_back({ abs(x[i].first - x[i + 1].first),{x[i].second, x[i + 1].second} });
        v.push_back({ abs(y[i].first - y[i + 1].first),{y[i].second, y[i + 1].second} });
        v.push_back({ abs(z[i].first - z[i + 1].first),{z[i].second, z[i + 1].second} });
    }
}

void solution() {
    findRoute();

    sort(v.begin(), v.end());

    for (int i = 0; i < N; i++) {
        p[i] = i;
    }

    for (int i = 0; i < v.size(); i++) {
        int a = v[i].second.first;
        int b = v[i].second.second;
        int c = v[i].first;

        if (!sameParent(a, b)) {
            unionParent(a, b);
            result += c;
        }
    }

    cout << result;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL); cout.tie(NULL);

    cin >> N;

    int a, b, c;
    for (int i = 0; i < N; i++) {
        cin >> a >> b >> c;
        x.push_back({ a,i });
        y.push_back({ b,i });
        z.push_back({ c,i });
    }

    solution();

    return 0;
}
```
